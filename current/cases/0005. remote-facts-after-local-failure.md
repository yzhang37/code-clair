# 本地记录失败时，保留已经确认的 LinkedIn 事实

## 目的

检查本地记录失败时，错误回传是否保留已确认的创建事实。

## 判断理由

本地记录与远端创建是不同操作，前者失败不能推翻后者的已确认结果。保留刊登身份和本次网页证据，上层才能核对并补记；把本地失败改判为未创建，可能导致再次发布已经创建的刊登。

## 边界

适用条件是已经确认创建并取得 LinkedIn Job ID，随后本地记录失败。下列注释均位于构造并抛出本地记录失败异常的接点。

普通点击或未满足确认条件的回执不能代替确认创建。

## 验收

- 说明写清本地记录失败时，异常继续携带已确认的 LinkedIn Job ID 和本次网页证据，供上层补记；不把本地失败解释为未创建或据此重新发布。
- 保留已确认事实的说明放在构造并抛出本地记录失败异常的接点。

## 反例

```cpp
// 本地记录失败，视为未创建，后续重新发布。
// Treat local recording failure as no creation and publish again later.
```

它把本地记录的失败当成远端未创建的证据，后续重发便可能重复创建。

## 正例

```less
// 本地记录失败时，异常继续携带已确认的 LinkedIn Job ID 和本次网页证据，供上层补记。
// On local recording failure, the error retains the confirmed LinkedIn Job ID and this attempt's web evidence for upstream recovery.
```

它保留了已确认创建的身份与证据，使上层能够针对这次已创建的刊登补记，而不把本地失败当成重新发布的依据。
