# 失败日志要能定位操作并说明原因

## 目的

检验本地结果记录失败的日志是否保留定位操作和判断原因所需的信息。

## 判断理由

日志只写“Posting failed”，读者无法区分网页发布失败与本地结果记录失败。关联当次操作、已知远端结果和本地安全原因，才能定位需要处理的失败。

## 边界

适用条件是本次操作的远端结果已确认创建，随后本地结果记录失败，且已核实当前边界负责记录故障。

## 验收

- 日志能定位本地结果记录失败，并关联当次 Action、已知远端结果和安全的原因信息。
- 日志正文使用英文，值来自当次操作，异常信息经过必要的脱敏处理。

## 反例

```text
ERROR Posting failed
```

这条记录没有区分网页发布与本地结果记录，也没有提供关联操作和判断原因的信息。

## 正例

```text
ERROR Posting result persistence failed action_id=example-action remote_outcome=created linkedin_job_id=123456789 error_code=ECONNRESET
```

这条记录把远端已创建与本地保存失败分开，用本次操作标识关联已知结果和安全的错误原因。
