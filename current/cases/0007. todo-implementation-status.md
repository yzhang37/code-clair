# 待实现的工作不能写成已经完成

## 目的

检查说明中的完成状态是否符合当前实现，尤其是 TODO 有没有把尚未补上的行为写成已有保证。

## 判断理由

待办明明没有完成，说明却写成“已经保存”，接手者就会误以为结果能够保留，漏掉真正需要补的工作。一个 TODO 标记不能抵消说明文字里的错误完成状态。

## 边界

适用条件是当前实现只把操作结果保存在内存中，尚未写入持久化存储；待办是补上持久化，避免进程重启后丢失结果。

示例的语言顺序为中文、英文。

- 必须先核实当前实现，不能只看见一次接口调用就猜测底层有没有完成工作。

## 验收

当前完成状态与已核实的实现一致，待补行为仍明确是待实现。

## 反例

```text
// TODO:
// 将结果写入持久化存储，避免进程重启后丢失；当前已经写入持久化存储。
// Persist the result so it survives a process restart; it is already stored durably.
```

共同前提是尚未持久化，说明却写成已经持久化，当前状态失实。

## 正例

```text
// TODO:
// 将结果写入持久化存储，避免进程重启后丢失；当前只保存在内存中。
// Persist the result so it survives a process restart; it is currently stored only in memory.
```

写明当前只保存在内存中，与尚未持久化的前提一致。
