# 业务选择要解释为什么，不能只复述动作

## 目的

检查非显然的业务选择、默认值或配置取舍是否说明选择理由。

## 判断理由

只看到“保留名额”，维护者可能把它当成漏释放，顺手改成释放。知道它是在防止名额被提前重复使用，才能判断这项行为该不该改。只写动作会丢掉维护这段代码所需的决策依据。

## 边界

适用条件是代码按既定约定在外部结果尚未确认时保留预留名额，且除了待判片段外没有其他说明解释这一选择的理由。

示例的语言顺序为中文、英文。

- 理由已由邻近说明讲清楚时，不要求重复。
- 理由必须有依据，不能为了补“为什么”编造业务约束。

## 验收

说明能够依据已有业务条件，讲清选择要避免的实际问题，支持读者判断改变行为的后果；仅复述动作或配置值不通过。

## 反例

```text
// 外部结果尚未确认时，保留预留名额。
// Keep the reserved capacity while the external outcome is unconfirmed.
```

只说了保留名额，没有说明为什么保留，缺少解释该选择的业务理由。

## 正例

```text
// 外部结果尚未确认时，保留预留名额，避免把可能仍被占用的名额误算为空闲。
// Keep the reserved capacity while the external outcome is unconfirmed so capacity that may still be in use is not counted as available.
```

说明了提前释放会把可能仍被占用的名额误算为空闲，读者能据此判断风险。
