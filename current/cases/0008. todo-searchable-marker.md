# 明确留待实现的说明不能缺少可检索的 TODO 标记

## 目的

检查明确留待后续实现的说明是否有可检索的 TODO 标记，避免待办只藏在普通说明里。

## 判断理由

说明正文可以讲清待补行为和原因，但不能代替任务标记。接手者按 TODO 检索待办时，没有标记的说明不会出现在结果中，明确需要补上的工作就可能被遗漏。

## 边界

适用条件是当前结果只保存在内存中，尚未写入持久化存储；已明确需要补上持久化，避免进程重启后丢失结果。

本例说明按每句中文、英文的顺序排列。

- 正常职责边界、普通无操作分支及未证实的问题，不因缺少 TODO 就按本例判错。

## 验收

- 明确待办有一个独立成行的 `TODO:` 公共标记，能够按该标记检索到对应说明。
- 原有待补行为、业务理由和当前未完成状态说明保持完整。

## 反例

```text
// 将结果写入持久化存储，避免进程重启后丢失；当前只保存在内存中。
// Persist the result so it survives a process restart; it is currently stored only in memory.
```

待补工作、理由和当前状态已经写清，但缺少可检索的 TODO 标记，按任务标记检索时会漏掉这项明确待办。

## 正例

```text
// TODO:
// 将结果写入持久化存储，避免进程重启后丢失；当前只保存在内存中。
// Persist the result so it survives a process restart; it is currently stored only in memory.
```

独立的 TODO 标记使这项待办可被检索，原说明仍如实保留尚未完成的状态和持久化理由。
