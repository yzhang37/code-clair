# 异常路径的注释不能把仍会尝试的处理写成成功后才执行

## 目的

检查异常路径的注释是否写清前一步失败后仍会尝试的处理，避免误写成成功后才执行。

## 判断理由

结果记录与 STOP 保护承担不同职责。前一步记录失败，不会自动取消后续执行保护的需要；把二者写成成功依赖，会使读者误解失败路径，并可能在维护时漏掉保护处理。

## 边界

适用条件是代码捕获结果记录失败后，仍会检查并尝试处理 `result.stop`。下列注释均位于 `if (result.stop)` 前。

- 本例中的 STOP 处理已经存在，不是尚待补上的行为。
- 本例给出的是仍会尝试处理的事实，没有给出保护已成功的证据。

## 验收

- 注释写清记录失败后仍尝试处理 STOP，并说明避免漏掉后续执行保护的理由。
- 不把已有处理写成待实现，也不把尝试处理写成已经成功执行保护。
- 说明该执行顺序的注释放在 `if (result.stop)` 前。

## 反例

```cpp
// 保存结果成功后，处理 STOP。
// Handle STOP after successfully saving the result.
```

把 STOP 处理写成依赖保存成功，与记录失败后仍会尝试处理的前提矛盾。

## 正例

```cpp
// 即使结果记录失败，仍尝试处理已有的 STOP，避免漏掉后续执行保护。
// Attempt to handle any existing STOP even if result recording fails, so protection for subsequent operations is still attempted.
```

保留了失败后仍尝试处理的关系，并解释保护动机，没有承诺保护已经成功。
