# 同一接点的业务说明不能重复解释同一条规则

## 目的

检查同一接点的业务说明是否存在没有增加信息的同语重复。

## 判断理由

没有增加条件或理由的复述，会增加阅读量，还要求维护者在同一次修改中同步多处表述；漏改时，同一规则就可能出现不一致的说法。

等义翻译让使用不同语言的读者理解同一条说明，承担的是语言对应的需要，不应当作同语复述删除。

## 边界

中英文对应是既定语言要求。

本例中，05 是移交前的负责方；写入“已提交”后，Slot 的释放责任已交给后续任务。

- 本例比较同一接点附近、没有增加条件或理由的重复说明。
- 函数总图与必要的就地说明仍需保留。
- 中英文等义配对本身不算冗余，不按注释行数判定。

## 验收

- 同一接点附近，同一种语言不再重复解释没有新增条件或理由的同一条规则。
- 删除重复表述后，原业务规则、必要说明和各语言版本保持完整。

## 反例一：从交接双方重复说明同一次责任转移

```cpp
// 写入「已提交」后，由后续任务释放 Slot。
// Once confirmed submission is recorded, a follow-up task releases the slot.
// 05 记下「已提交」后，不再负责释放这个名额。
// Capability 05 no longer releases the slot after recording confirmed submission.
```

在释放责任已移交的前提下，“由后续任务释放”和“05 不再负责释放”从双方描述同一次责任转移，没有增加条件、行为或理由。

## 反例二：用不同措辞重复说明接手方的责任

```cpp
// 写入「已提交」后，由后续任务释放 Slot。
// Once confirmed submission is recorded, a follow-up task releases the slot.
// 「已提交」记下以后，后续任务释放这个名额。
// After confirmed submission is recorded, a follow-up task releases the slot.
```

同一种语言再次说明由后续任务释放同一个名额，没有增加条件、行为或理由。

## 正例

```cpp
// 写入「已提交」后，Slot 的释放责任交给后续任务。
// Once confirmed submission is recorded, a follow-up task owns responsibility for releasing the slot.
```

保留了一次完整的责任交接说明及等义译文，业务含义没有因去重而丢失。
